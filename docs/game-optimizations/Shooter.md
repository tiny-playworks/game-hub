# 飞机大战 (Shooter) 重制优化计划

## 1. 当前现状与痛点
- **表现力不足**：通常只有基础形状的飞机和子弹，爆炸仅仅是物体消失，缺乏空战的激烈氛围。
- **弹幕单调**：子弹是单点直线发射，敌机行为模式单一，缺乏躲避的挑战乐趣。

## 2. 视觉与动效升级 (Juice & Polish)
- **动画序列图爆炸**：使用逐帧 Sprite 动画或粒子发射系统，代替直接删除敌机。敌机死亡时爆出多团火焰特效。
- **视差滚动背景 (Parallax)**：利用多层透明背景图（如：远处的星空缓慢，近处的云层或陆地快速向下滚动），营造飞行的高速感。
- **飞机倾斜姿态**：当按下左键或右键时，玩家战机要有明显的侧倾（Roll）角度动画，停止时恢复。
- **激光/弹道特效**：子弹不应是简单的方块，而应是两端带透明渐变的“激光束”，并具有发射口的枪口火焰（Muzzle Flash）。

## 3. 听觉与反馈体验
- BGM 引擎轰鸣的白噪音作为底噪。
- 子弹发射时的 "Biu-biu" 声（根据射速动态微调 Pitch 避免听觉疲劳）。
- 爆炸声分层：普通敌机轻微的 "Boom"，Boss 或者全屏炸弹（Bomb）具有低频的 "KABOOM" 震撼音。

## 4. 机制与周边创新
- **武器升级树系统**：击毁特定红星敌机掉落强化道具。吃满后从单发变为双发散弹，甚至带有跟踪导弹。
- **全屏必杀技 (Bomb)**：加入清屏大招，使用时全屏反白，所有弹幕与敌机清空，极大地提高容错率和观赏性。
- **敌机轨迹脚本化**：引入多种编队行为（如：V字形、S曲线切入等），而不仅是单纯从上往下掉。

## 5. 代码重构指引
- 需要一个健壮的 **Object Pool（对象池）** 来管理海量的子弹和特效粒子，避免 JavaScript 频繁创建销毁对象触发 GC 导致画面卡顿。
- 使用统一的 `tick` 更新循环，按帧计算每颗子弹的位置；并且需要用高效的四叉树（QuadTree）或空间网格划分来优化敌我碰撞检测。
