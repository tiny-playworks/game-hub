# 2048 优化评估

## 源码入口

- 页面：`src/pages/Game2048.tsx`
- 样式：`src/pages/2048.css`
- 规则 Hook：`src/hooks/use2048Engine.ts`

## 当前状态

2048 已经不是旧文档里描述的“逻辑和页面完全耦合”状态。当前版本有独立 Hook、唯一 tile id、滑动动画、新砖块动画、合并动画、撤销、连击和移动端虚拟手柄。

## 已落地优化

- tile 使用 `id/r/c/value`，支持动画追踪。
- 支持最近 5 步撤销。
- 支持 combo 展示，并写入 `useGameStore` 的 `maxCombo`。
- 支持深色虚拟手柄，浅色背景下可见。
- 高分接入 `useGameStore`。

## 待优化问题

- `use2048Engine` 内部仍会直接改 `state.tiles` 中取出的 tile 对象，再复制到新对象；这会增加历史记录和动画状态串扰风险。
- Hook 同时负责规则、随机生成、历史栈和 React 状态，测试粒度还不够干净。
- 页面渲染中读取 `window.innerWidth` 决定 tile padding，属于渲染期环境判断，后续可交给 CSS。
- 没有真正的触屏滑动手势，只能点虚拟方向键。
- 合并后的消失 tile 依赖 `mergedInto` 保留在集合里，动画结束清理策略还可以更明确。

## 建议重构

- 抽出纯规则模块：`moveBoard(state, dir, rng)`、`spawnTile(board, rng)`、`isGameOver(board)`。
- Hook 只负责调用纯规则、维护 history 和暴露 UI 状态。
- tile 动画状态用单独的 transient 字段管理，避免污染可持久化规则状态。
- 用 CSS container 或 grid gap 解决 padding，不在 JSX 内读取窗口宽度。

## 优先级

- P0：消除规则层对象原地修改，补 history 不串扰测试。
- P1：补触屏 swipe；补 2048 达成状态而不是只到 game over。
- P2：加入更轻的音效、合并闪光和大数字成就提示。

## 验证建议

- 单测覆盖同一行双合并、不能重复合并、撤销恢复、满盘可合并/不可合并。
- 浏览器验证桌面键盘、移动端虚拟手柄和深浅主题。
