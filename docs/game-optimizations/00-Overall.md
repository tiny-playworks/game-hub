# 小游戏优化总览

## 范围

本目录只覆盖 `src/data/games.ts` 中 `categoryId: 'mini'` 的小游戏：

- 猜数字
- 井字棋
- 记忆翻牌
- 2048
- 贪吃蛇
- 打砖块
- 飞机大战
- 坦克大战
- 俄罗斯方块
- 3D 魔方

棋类、麻将、扑克类规则体量明显更大，后续应单独建规则与体验评估，不混在本轮小游戏优化里。

## 当前共性状态

- 已有 React 页面路由和主页游戏清单。
- `useGameStore` 已支持部分游戏的高分、游玩次数、连击等统计。
- `VirtualController` 已支持移动端方向键、动作键、深浅两套色调和按下/松开事件。
- `useScreenShake` 已被部分游戏用于失败、合并、命中反馈。
- 2048、俄罗斯方块、3D 魔方已经有较明显的逻辑/渲染拆分；贪吃蛇刚补了自撞规则辅助函数。
- 打砖块、飞机大战、坦克大战仍主要是组件内 Canvas 循环，规则、渲染、输入混在一起。

## 总体问题

### P0：影响可玩性或一致性的点

- 部分游戏仍残留英文 UI 或英文状态文案，中文站点体验不统一。
- 移动端可玩性不一致：2048、贪吃蛇、飞机、坦克已补手柄；俄罗斯方块和 3D 魔方仍需要更明确的移动端操作层。
- 高分和成长系统接入不一致：打砖块、飞机、坦克、俄罗斯方块仍有不同程度的本地状态或缺失统计。
- Canvas 游戏大多把游戏循环放在 React 组件里，状态更新和绘制耦合，后续继续加特效会越来越难维护。

### P1：规则和架构优化

- 把贪吃蛇、打砖块、飞机、坦克的核心规则抽到 `src/lib/`，让页面只负责输入、渲染和 HUD。
- 对依赖随机数的游戏提供可注入 RNG，便于测试和复现。
- 统一暂停、重新开始、失败、胜利状态模型，避免每个游戏各写一套。
- 统一成就、高分、局内统计更新时机，减少“游戏结束才更新”和“即时更新”混用。

### P2：表现力和内容扩展

- 建立轻量音效约定，优先用已有 `use-sound`，只做点击、命中、失败、胜利等短音效。
- 为 Canvas 游戏补基础粒子、拖尾、命中闪烁，不急着引入复杂美术管线。
- 加入难度曲线、模式选择和简短局内提示，但避免把轻量小游戏做成复杂系统。

## 推荐实施顺序

1. 先修 P0：中文一致性、移动端可玩性、高分统计一致性。
2. 再抽规则：优先处理打砖块、飞机、坦克，因为它们现在最依赖组件内循环。
3. 再做表现力：音效、粒子、动效必须建立在规则稳定之后。
4. 最后扩机制：Boss、道具、关卡、模式等都放到对应游戏已有手感稳定后再做。

## 验证建议

- 每次改小游戏都至少跑 `pnpm run typecheck` 和对应 `rstest`。
- 涉及 Canvas 或 3D 时，用桌面和 390px 宽移动视口各打开一次。
- 涉及规则时，优先补纯函数测试，不只靠页面快照。
