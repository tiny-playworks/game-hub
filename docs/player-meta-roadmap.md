# 玩家成长 / 音频 / 雀士角色路线图

## 1. 目标

这轮不直接做重型账户系统，也不把雀士角色一次做完。

优先补三件事：

1. 玩家身份感
2. 游戏反馈感
3. 持续成长感

核心判断：

- 先做 **本地玩家档案**，不急着上真实登录。
- 先做 **成就 / 称号 / 任务 / 统计**，把 meta 层立起来。
- 先做 **音频系统 1.0**，再考虑大量角色语音。
- **雀士角色** 单独作为一个重版本处理。

---

## 2. 当前现状

### 2.1 已有基础

- 游戏总数：16
- 成就：14 项，本地解锁
- 日麻已有部分 wav 与 TTS 兜底
- 日麻主题与最近游玩已有少量本地存储

### 2.2 当前短板

- 没有真正的玩家档案页
- 没有昵称、头像、称号体系
- 成就更像静态展示，不像成长系统
- 日麻缺少完整对局音效、BGM、结算反馈
- 角色系统没有数据层、UI 层、资源层骨架

---

## 3. 总体原则

1. 先轻后重
2. 先做本地化 meta 系统，再碰真实账户
3. 先做通用音频，再做角色语音包
4. 先做角色系统骨架，再做立绘和语音资源
5. 不把“账户 / 成就 / 角色 / 音频”混成一个大需求

---

## 4. 分阶段计划

## Phase 1 - 本地玩家档案 1.0

目标：先让玩家“有身份”。

建议内容：

- 昵称
- 默认头像
- 玩家卡
- 称号展示位
- 常用牌桌主题
- 音量设置

产出：

- `playerProfile` 本地存储结构
- 首页或大厅入口的玩家卡
- 设置面板里的基础偏好项

完成标准：

- 玩家进入站点后，不再只是“匿名访客”
- 玩家能看到自己的昵称、头像、称号和偏好

---

## Phase 2 - 成长系统 1.0

目标：把成就页升级成真正的 meta 系统。

建议内容：

- 成就点数
- 稀有度
- 进度型成就
- 分类
- 奖励称号
- 每日任务
- 周任务
- 基础统计

统计建议先做：

- 总游玩次数
- 各游戏游玩次数
- 日麻局数
- 日麻和牌次数
- 日麻立直次数
- 日麻自摸次数

签到系统建议（放在 Phase 2）：

- 每日签到 1 次（北京时间 0 点刷新）
- 连续签到计数与累计签到计数
- 7 天里程碑奖励
- 30 天里程碑奖励
- 奖励先发成长点，预留后续“物品奖励”扩展位

签到状态结构建议：

```ts
interface CheckinState {
  dateKey: string;          // 今日是否已签到（北京时间）
  streakDays: number;       // 连续签到天数
  totalDays: number;        // 累计签到天数
  weekClaimedAt: number[];  // 已领取的 7 天里程碑
  monthClaimedAt: number[]; // 已领取的 30 天里程碑
  updatedAt: number;
}
```

产出：

- 新的成就数据结构
- 任务数据结构
- 统计存储结构
- 成就页 2.0
- 玩家卡上的称号与成长信息

完成标准：

- 玩家玩一局之后，能明显看到“我获得了什么”
- 成就页从列表变成成长面板
- 签到可形成周/月节奏奖励闭环

---

## Phase 3 - 音频系统 1.0

目标：先把“像游戏”的声音基础做出来。

优先级：

### P0

- UI 点击音
- 日麻出牌音
- 日麻摸牌音
- 日麻和了提示音
- 日麻流局提示音
- 日麻大厅 / 对局 BGM

### P1

- 倒计时警告音
- 宝牌翻开音
- 结算页短音乐

### P2

- 多套 BGM
- 多套 UI 音色风格

语音建议：

- 先做“系统语音包”，不要一开始做很多角色配音
- 短句优先：
  - リーチ
  - ツモ
  - ロン
  - ポン
  - チー
  - カン
  - 流局

技术建议：

- 音量分组：
  - BGM
  - 音效
  - 语音
- 保留失败回退策略：
  - wav 优先
  - TTS 兜底

AI 资源方向：

- 语音：ElevenLabs
- 音效 / BGM：Stable Audio 优先
- 风格探索：Suno / Udio 仅作参考与试样

注意：

- 商用与归属必须在正式落库前再看一次官方条款
- AI 生成结果不能直接无筛选入库

完成标准：

- 首页不再是静态网页感
- 日麻对局中每个关键动作都有反馈
- 结算时有明确的完成感

---

## Phase 4 - 游戏感改造

目标：让站点更像“游戏大厅”，不是普通导航页。

建议内容：

- 首页大厅化
- 玩家卡常驻
- 最近游玩入口
- 每日任务入口
- 解锁弹窗
- 结算反馈页增强
- 收藏入口

建议重点：

- 首页要像大厅
- 日麻结算页要像结算页
- 解锁反馈要有即时爽点

完成标准：

- 用户进入首页就知道自己在一个游戏项目里
- 完成一局后有明显的反馈闭环

---

## Phase 5 - 雀士角色系统预研

目标：先把重功能拆清楚，不急着上完整内容。

先定义：

- 角色数据结构
- 角色稀有度
- 角色语音包位
- 角色立绘位
- 角色解锁方式
- 角色是否影响玩法

建议先定结论：

- 第一版角色 **只影响表现，不影响强度**
- 不做数值养成
- 不做复杂抽卡
- 不做剧情系统

先做骨架：

- 角色选择入口
- 角色占位立绘
- 角色资料卡
- 角色语音包切换位

完成标准：

- 角色系统可以挂资源
- 角色系统不反向拖累主玩法

---

## Phase 6 - 雀士角色 1.0

目标：正式做出第一版雀士系统。

建议内容：

- 4 个基础雀士角色
- 每个角色一套立绘
- 每个角色一套基础语音
- 角色资料页
- 角色解锁条件

第一版先只做这些语音：

- 立直
- 吃
- 碰
- 杠
- 自摸
- 荣和
- 流局

暂不做：

- 剧情
- 皮肤换装
- 角色羁绊
- 强度差异

---

## 5. 明天建议执行范围

不要明天一口气开太大。

建议只做下面两段：

### 明天必做

1. 本地玩家档案 1.0 骨架
2. 成长系统 1.0 的数据结构重构

### 明天可选

1. 音频系统 1.0 的目录与配置骨架

### 明天不要做

- 真登录
- 云存档
- 完整雀士角色系统
- 大量 AI 资源生产

---

## 6. 执行顺序建议

1. 先定玩家档案数据结构
2. 再定统计 / 成就 / 任务数据结构
3. 然后统一本地存储键与读取入口
4. 再补玩家卡 UI
5. 最后补音频系统分组与资源位

---

## 7. 一句话版本

先把“玩家是谁、玩完得到了什么、操作时有没有反馈”做好，再进入重型的雀士角色系统。
